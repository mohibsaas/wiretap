# First-time setup

This guide walks through installing Wiretap, configuring API keys, and running your first simulation.

---

## Prerequisites

| Requirement | Version | Notes |
|-------------|---------|-------|
| Python | ≥ 3.11 | Required |
| [uv](https://docs.astral.sh/uv/) | Latest | Package manager and installer |
| LLM API key | — | OpenAI or Anthropic (default simulator + judge) |
| Speech API key | — | PyAI by default (STT/TTS for voice tests) |
| Platform API key | — | Only if dialing a live agent (Retell, Vapi, etc.) |

Node.js ≥ 18 is only needed if you want to build or develop the local UI.

---

## Step 1 — Install Wiretap

```bash
git clone https://github.com/mohibsaas/wiretap.git
cd wiretap
uv sync
uv tool install --editable .
```

Verify the install:

```bash
wiretap --version
```

Optional extras:

```bash
uv sync --extra pstn   # Real phone calls via Twilio
uv sync --extra mcp    # MCP server for coding agents
uv sync --extra dev    # pytest + ruff
```

## Step 2 — Configure keys

All secrets go in **`~/.wiretap/.env`** (or `$WIRETAP_HOME/.env`). Wiretap never writes keys into suite YAML.

### Minimum keys (always required)

These power the **test caller** (simulator) and **judge** — Wiretap's own LLM and speech stack:

| Key | Purpose | Where to get it |
|-----|---------|-----------------|
| `OPENAI_API_KEY` | Default LLM for simulator + judge | [platform.openai.com](https://platform.openai.com/) |
| `PYAI_API_KEY` | Default STT/TTS for voice tests | [py.ai](https://py.ai/) |

**Alternative:** use Anthropic instead of OpenAI for the LLM:

| Key | Purpose |
|-----|---------|
| `ANTHROPIC_API_KEY` | LLM for simulator + judge (if not using OpenAI) |

You need **one LLM key** (OpenAI or Anthropic) **plus one speech key** (PyAI by default) to run voice simulations.

### Platform keys (required to dial a live agent)

Add the key for whichever platform hosts your deployed agent:

| Platform | Required key(s) | Notes |
|----------|-----------------|-------|
| **Retell** | `RETELL_API_KEY` | LiveKit web calls |
| **Vapi** | `VAPI_API_KEY` | WebSocket PCM voice |
| **ElevenLabs Agents** | `ELEVENLABS_API_KEY` | ConvAI WebSocket (same key as ElevenLabs TTS) |
| **LiveKit Agents** | `LIVEKIT_API_KEY` + `LIVEKIT_API_SECRET` | Or set `LIVEKIT_TOKEN` to skip key/secret |
| **LiveKit Agents** | `LIVEKIT_URL` | WebSocket URL (e.g. `wss://…`) |
| **Synthflow** | `SYNTHFLOW_API_KEY` | Also needs `SYNTHFLOW_FROM_NUMBER` + `SYNTHFLOW_TO_NUMBER` |
| **Bland** | `BLAND_API_KEY` | Import only — dial via phone (PSTN) |
| **Bolna** | `BOLNA_API_KEY` | Import only — dial via phone (PSTN) |
| **Custom / CI stub** | None | Uses `transport: text` — no live dial |

### Phone / PSTN keys (optional)

Only needed for `--transport phone` or `--transport pstn`:

| Key | Purpose |
|-----|---------|
| `TWILIO_ACCOUNT_SID` | Twilio account |
| `TWILIO_AUTH_TOKEN` | Twilio auth |
| `TWILIO_FROM_NUMBER` | Caller ID to dial from |

Install the PSTN extra first: `uv sync --extra pstn`

`TWILIO_SIP_PASSWORD` is auto-generated by Wiretap — do not set it manually.

### Alternative speech providers (optional)

Replace PyAI by configuring a different STT/TTS provider during setup:

| Key | Provider |
|-----|----------|
| `DEEPGRAM_API_KEY` | Deepgram STT |
| `CARTESIA_API_KEY` | Cartesia TTS |
| `ELEVENLABS_API_KEY` | ElevenLabs TTS |
| `ASSEMBLYAI_API_KEY` | AssemblyAI STT |
| `GLADIA_API_KEY` | Gladia STT |
| `GROQ_API_KEY` | Groq (LLM or speech) |
| `PLAYHT_API_KEY` + `PLAYHT_USER_ID` | PlayHT TTS |
| `LMNT_API_KEY` | LMNT TTS |
| `RIME_API_KEY` | Rime TTS |

See [`.env.example`](../.env.example) for the complete list of supported keys.

## Step 3 — Interactive setup (recommended)

Run the first-run wizard. It walks through all four setup steps:

```bash
wiretap init
```

| Step | What it configures |
|------|-------------------|
| **1. Simulator** | LLM provider + model, STT provider, TTS provider + voice |
| **2. Live agent** | Platform selection, API key prompt, agent import |
| **3. Test suite** | Category-based scenario generation |
| **4. Phone (optional)** | Twilio credentials for PSTN dialing |

Keys are written to `~/.wiretap/.env` with `chmod 600`. Values are never printed to the terminal.

Verify everything is configured:

```bash
wiretap status
```

Example output (no secret values shown):

```text
Simulator    configured
LLM          openai / gpt-4o-mini
STT          pyai
TTS          pyai
Platform     retell
Agent        agent_abc123
Suite        retell_agent_abc123
Keys         OPENAI_API_KEY ✓  PYAI_API_KEY ✓  RETELL_API_KEY ✓
```

## Step 4 — Manual setup (non-interactive / CI)

If you cannot run the interactive wizard (CI, headless server):

```bash
mkdir -p ~/.wiretap
chmod 700 ~/.wiretap

cat > ~/.wiretap/.env <<'EOF'
OPENAI_API_KEY=sk-...
PYAI_API_KEY=...
RETELL_API_KEY=...
EOF
chmod 600 ~/.wiretap/.env
```

Then import and simulate:

```bash
wiretap import retell --agent-id agent_xxx
wiretap simulate --suite retell_agent_xxx --all
wiretap report
```

For CI text-only smoke tests (no voice dial cost):

```bash
wiretap simulate --suite my-suite --all --transport text --concurrency 1
```

---

## Step 5 — Run your first simulation

After setup:

```bash
# Run all scenarios in your suite
wiretap simulate --suite <suite-name> --all

# View results
wiretap report
```

Common flags:

| Flag | Purpose |
|------|---------|
| `--scenario <id>` | Run a single scenario |
| `--transport web` | WebSocket/LiveKit dial (default for voice platforms) |
| `--transport phone` | PSTN dial via Twilio |
| `--transport text` | Text stub — fast, no voice cost (CI) |
| `--concurrency 1` | Run one scenario at a time (safest for first run) |
| `--strict` | Stricter test-agent behavior; harness faults → inconclusive |

## Step 6 — Local UI (optional)

Build and launch the browser dashboard:

```bash
cd ui && npm install && npm run build && cd ..
wiretap ui run
# → http://127.0.0.1:8787
```

The UI runs the same onboarding flow as `wiretap init` — configure keys, connect an agent, generate suites, and start batch runs from the browser.

## Key requirements by use case

### Quick reference

| Use case | Required keys |
|----------|---------------|
| **Voice test against Retell agent** | `OPENAI_API_KEY` + `PYAI_API_KEY` + `RETELL_API_KEY` |
| **Voice test against Vapi agent** | `OPENAI_API_KEY` + `PYAI_API_KEY` + `VAPI_API_KEY` |
| **Voice test against ElevenLabs agent** | `OPENAI_API_KEY` + `PYAI_API_KEY` + `ELEVENLABS_API_KEY` |
| **Voice test against LiveKit agent** | `OPENAI_API_KEY` + `PYAI_API_KEY` + `LIVEKIT_API_KEY` + `LIVEKIT_API_SECRET` + `LIVEKIT_URL` |
| **Phone test (any agent)** | Above keys + `TWILIO_ACCOUNT_SID` + `TWILIO_AUTH_TOKEN` + PSTN extra |
| **CI text-only smoke test** | `OPENAI_API_KEY` only (no speech or platform keys) |
| **Anthropic instead of OpenAI** | `ANTHROPIC_API_KEY` + `PYAI_API_KEY` + platform key |

### Cost note

Wiretap itself is free (MIT). You pay your own API providers:

- **LLM tokens** — simulator generates test-caller lines; judge scores each call
- **Speech API** — STT/TTS per utterance on voice transports
- **Platform minutes** — Retell, Vapi, etc. bill per dial
- **Twilio minutes** — PSTN calls

Use `--transport text` in CI to avoid speech and dial costs.

## Troubleshooting setup

| Problem | Fix |
|---------|-----|
| `wiretap init needs an interactive terminal` | Set keys manually in `~/.wiretap/.env` (see Step 4) |
| Key shows as missing in `wiretap status` | Check key name matches `.env.example` exactly; no quotes needed |
| `RETELL_API_KEY required` | Add platform key to `.env`; run `wiretap status` to verify |
| Speech not configured | Add `PYAI_API_KEY` or configure alternate STT/TTS in `wiretap simulator configure` |
| Cannot list remote agents | Key may be invalid — check auth; paste agent ID manually |
| Phone setup incomplete | Run `uv sync --extra pstn`; add Twilio SID + auth token |
